Artifact Overview

The artifact used for this enhancement is the Travlr Getaways full-stack web application originally developed in CS 465. Travlr uses MongoDB as its database and Mongoose to define and interact with application data.

The original database primarily stored trip information such as trip codes, names, resort details, dates, prices, images, and descriptions. The backend REST API allowed the application to retrieve and manage this data.

Original Database Design

The original Travlr database was functional but relatively simple. Most of the stored data focused on the trip records themselves.

MongoDB provided persistent storage, while Mongoose was used to define the trip schema and communicate between the Node.js backend and the database.

The REST API acted as the connection between the frontend and the database. Instead of communicating directly with MongoDB, the application sent requests through API routes and controller logic.

Trip Reviews Enhancement

For my database enhancement, I expanded the Travlr application by adding Trip Reviews functionality.

The purpose of this enhancement was to move beyond storing only basic trip information and introduce additional data associated with the travel experience.

Adding reviews increased the complexity of the database because the application now needed to manage information beyond the original trip records. The enhancement required changes to how review data was represented, retrieved, and integrated into the rest of the full-stack application.

This demonstrates that database changes often affect more than the database itself. Changes to stored data can also require updates to backend controllers, API routes, application services, and the frontend interface.

MongoDB and Mongoose

Travlr uses MongoDB for persistent data storage and Mongoose for schema definition and database communication.

Mongoose provides a structured way for the Node.js application to work with MongoDB documents. By defining expected fields and data types, the application can better control how information is represented and stored.

Expanding the application with review functionality strengthened my understanding of how database schemas need to support the requirements of the application while remaining organized and maintainable.

REST API and CRUD Concepts

The database layer is connected to the rest of Travlr through a REST API. Requests move from the frontend to API routes and controllers before Mongoose communicates with MongoDB.

This structure supports CRUD concepts such as creating, reading, and updating application information while maintaining separation between the user interface and the database.

The Trip Reviews enhancement required me to think about how new database functionality should be exposed through the API and how the frontend would consume that information.

Validation and Security

Database security is an important consideration whenever an application accepts information from users.

User-provided data should be validated before it is stored in the database. Validation helps prevent incomplete, incorrect, or unexpected information from becoming part of the application data.

Authentication and authorization are also important when database operations can create or modify stored information. The application needs to determine which operations should be publicly available and which should require an authenticated user.

These considerations reinforced the idea that database development and secure software design are closely connected.
