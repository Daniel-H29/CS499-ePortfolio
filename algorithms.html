Artifact Overview

The artifact used for this enhancement is the Travlr Getaways full-stack web application originally developed in CS 465. The administrative portion of Travlr retrieves trip information from the backend and stores the returned records as a collection of Trip objects.

I selected this application for the algorithms and data structures category because the existing collection of trip objects provided an opportunity to apply algorithmic processing to data that was already being used by the application.

Original Functionality

In the original application, trip records were retrieved from the REST API and stored in a TypeScript array. Angular then iterated through the array and displayed each trip in the administrative interface.

Although this worked for displaying the information, the administrator had limited control over how the collection was organized. Trips were primarily displayed in the order they were received from the backend.

Sorting Enhancement

For my algorithms and data structures enhancement, I added sorting functionality to the administrative trip listing.

The enhancement works with the existing array of Trip objects and applies comparison logic to organize the collection according to trip properties. This allows the application to process the data before it is displayed rather than simply presenting the records in their original order.

The sorting functionality improves the usability of the administrative interface because trip information can be organized more efficiently as the collection grows.

Data Structures

The main data structure involved in this enhancement is an array containing Trip objects. Each Trip object contains several properties describing the travel package.

Because the records are represented as objects inside an array, comparison operations can examine specific object properties when determining how the collection should be ordered.

This demonstrates how data structures and algorithms work together. The array provides an organized structure for storing the collection, while the sorting logic determines how the objects within that structure are arranged.

Algorithmic Trade-Offs

An important consideration for this enhancement was deciding where the sorting operation should occur.

For the current Travlr application, client-side sorting is an appropriate solution because the number of trip records is relatively small and the collection is already loaded into memory by the Angular application.

This approach provides responsive sorting without requiring another request to the server every time the user changes the organization of the records.

However, the same approach may not be appropriate for a much larger dataset. If the application contained thousands or millions of records, retrieving the entire collection and sorting it in the browser could become inefficient.

In a larger production system, sorting could instead be performed through the backend or directly through MongoDB and combined with pagination. This would reduce the amount of data transferred to the client and limit the number of records that need to be processed at one time.

Course Outcome Alignment

This enhancement demonstrates my ability to design and evaluate a computing solution using algorithmic principles. I identified a limitation in the way the existing application organized its data and implemented sorting functionality to improve the usefulness of the trip collection.

The enhancement also demonstrates consideration of design trade-offs. Client-side sorting is appropriate for the current application, while server-side or database-level sorting would be more appropriate if Travlr were working with a significantly larger dataset.

Implementing the enhancement also required troubleshooting the flow of data between the service, Angular component, and HTML template. This strengthened my understanding of how algorithms can be integrated into a larger software system rather than being used only as isolated programming exercises.
